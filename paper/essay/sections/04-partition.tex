\section{Keyspace Partition Strategy}\label{sec:partition}
The search space is every length-6 string over the base-36 alphabet, of size
$N = 36^6 = 2{,}176{,}782{,}336$. Each integer index $i \in [0, N)$ maps to a
key by little-endian positional encoding over the alphabet, so a \emph{contiguous}
index interval corresponds to a set of distinct keys with no overlap between
intervals. The master divides $[0,N)$ into fixed-size chunks of $C$ keys, giving
$\lceil N/C \rceil$ chunks (e.g.\ $C = 5\times10^6$ yields 436 chunks), and
serves chunk ids from a queue.

\begin{algorithm}[H]
\small
\caption{Dynamic, non-overlapping assignment}
\begin{algorithmic}
\STATE pending $\leftarrow$ queue$(0,1,\dots,\lceil N/C\rceil-1)$;\; inflight $\leftarrow \emptyset$
\WHILE{a \texttt{REQUEST} arrives and not found}
  \IF{pending $\neq \emptyset$}
     \STATE $c \leftarrow$ pop(pending);\; inflight$[c] \leftarrow$ (worker, now)
     \STATE send \texttt{ASSIGN}$(c,\, cC,\, \min((c{+}1)C, N))$
  \ELSIF{inflight $\neq \emptyset$}
     \STATE send \texttt{NOWORK} \COMMENT{outstanding chunk may be requeued}
  \ELSE
     \STATE mark exhausted;\; broadcast \texttt{STOP}
  \ENDIF
\ENDWHILE
\end{algorithmic}
\end{algorithm}

Dynamic (pull-based) assignment rather than a static up-front split means
heterogeneous or contended workers stay balanced automatically, and it composes
cleanly with failure recovery: a chunk is only ever ``done'' when its
\texttt{DONE} arrives, so a lost chunk can be safely re-queued
(\autoref{sec:death}).
